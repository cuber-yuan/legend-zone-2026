  1. Sign in and create a Tank Battle match from Game Tables on the homepage, setting one or both seats to Human, then start the match.
  2. Each side commands two tanks. Hover over or tap a friendly tank to show its order controls. Follow the order indicator to see which side is answering.
  3. Use a directional button to move one cell. Toggle the central fire button, then choose a direction to shoot. Select hold to stay still. Disabled actions are currently illegal.
  4. Order every surviving tank. The pair of orders is submitted automatically when both tanks have orders; destroyed tanks require no input.
  5. Both sides act in the same round. If both seats are Human, the same device collects orders for each seat in turn. Spectators and replays cannot issue orders.

This minimal starter stays in place and randomly fires when the cooldown permits. It demonstrates the two-tank output format without requiring a full battlefield simulator.

import json
import random

def main():
    data = json.loads(input())
    my_side = data["requests"][0]["mySide"]
    previous = data["responses"][-1] if data["responses"] else [-1, -1]
    actions = []
    for last_action in previous:
        # A tank cannot fire in consecutive rounds.
        if last_action >= 4:
            actions.append(-1)
        else:
            actions.append(random.choice([-1, 4, 5, 6, 7]))
    print(json.dumps({"response": actions}))

if __name__ == "__main__":
    main()
{% endcall %} {% call section('I/O Format Specification', 'io-spec') %}

Read one JSON object containing requests and responses from stdin. Write one JSON object containing a two-element response array to stdout.

Input history

  • requests[0] contains mySide (0=Blue/top, 1=Red/bottom) and the initial terrain arrays brickfield, waterfield, and steelfield.
  • requests[1:] contains the opponent's previous two-tank actions, in round order.
  • responses contains your own previous two-tank actions. For completed round i, pair responses[i] with requests[i + 1]. These arrays store action values directly, without the outer response wrapper.
{
  "requests": [
    {"mySide": 0, "brickfield": [0, 0, 0], "waterfield": [0, 0, 0], "steelfield": [0, 0, 0]},
    [-1, -1]
  ],
  "responses": [[-1, -1]]
}

Coordinates and terrain

The battlefield is 9×9 with zero-based coordinates: x increases rightward and y downward. Blue tanks 0 and 1 start at (2,0) and (6,0); Red tanks 0 and 1 start at (6,8) and (2,8). Bases are at (4,0) and (4,8).

Each terrain array contains three 27-bit masks. Array element i describes rows 3*i through 3*i+2. Cell (x,y) is occupied when (field[y // 3] >> ((y % 3) * 9 + x)) & 1 equals 1. Replay both players' histories to track tanks, destroyed terrain, and cooldowns.

Output and action codes

{"response": [2, -1]}

The first entry orders tank 0, the second tank 1. In this example tank 0 moves down and tank 1 holds. Use -1 for a destroyed tank's slot.

{% endcall %} {% call section('Regulations', 'regulations') %}
  • Each side has one base and two tanks. Both players choose orders before the round is resolved; tanks move before shots are resolved.
  • A move advances one cell and must target an empty in-bounds cell in the current battlefield. Bricks, steel, water, bases, and currently occupied tank cells block movement.
  • A shot travels in a straight line to the first blocking object. It can destroy bricks, tanks (including friendly tanks), and bases. Steel blocks shots and survives; shots pass over water.
  • A tank cannot shoot in two consecutive rounds. It must move or hold on the following round.
  • A side loses when its base is destroyed or both of its tanks are destroyed. If both sides lose in the same round, the game is a draw.
  • The default round limit is 100. If both sides survive that limit, the game is a draw.
  • Malformed orders or illegal actions for a surviving tank forfeit the game. Destroyed tanks' orders are ignored. Opposing single tanks shooting directly at one another in opposite directions cancel those shots.
